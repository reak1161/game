# アーキテクチャ

## 構成

- `src/game/types.ts`: ゲーム状態、カード、コマンドの型
- `src/game/cards.ts`: 基本65枚と追加36枚の定義、追加セット選択と保留カードを除いた山札生成（両セット93枚）
- `src/game/v03-cards.ts`: 追加セットの36種類のカード定義。
- `src/game/v03-rules.ts`: 生存人数、対象禁止、常時設置、追加ターン予約、勝利リンクの撤去、死亡世代の判定。
- `src/game/v03-effects.ts`: 共通EffectContextの回復・ドロー・攻撃・選択・キューを組み合わせた新カード固有処理。エンジンやUIから独立する。
- `src/game/v03-reactions.ts`: 行動解決前の誘発、対象変更・反転、ダメージ時のカウンター・受け流し、補充後の口封じ。
- `src/game/card-numbers.ts`: 猟師の鋏用の設計書本文の数値データ。短縮UI説明・ローカライズに依存しない。
- `src/game/engine.ts`: ゲーム作成、カード使用、ターン進行、勝利判定
- `src/network/protocol.ts`: クライアント・サーバー間のメッセージと公開状態
- `server/index.ts`: 部屋、接続、秘密情報の除去、WebSocket配信、静的ファイル配信
- `server/cpu.ts`: CPU本人用に秘匿処理した状態から次のコマンドを決定する。部屋ごとの単一タイマーで900msおきに実行し、人間の切断中・勝敗確定後は停止する。
- `scripts/cpu-smoke.mjs`: 独立した一時サーバーで人数・開始権限・CPU進行・切断/再接続・秘密情報・ホスト交代を確認し、既存のオンラインスモークも実行する。
- `src/App.tsx`: オンライン接続、待機室、画面切り替え
- `src/GameBoard.tsx` / `src/battle.css` / `src/battle-interaction.css`: 卓、各席の手札・役職・捨て札、ロックオン、折りたたみ履歴、表示差分に対する有限アニメーション
- `src/battle-interaction.ts`: ドラッグ元と使用先からコマンドを選択する純粋関数。最終的なルール判定はサーバーが行う。
- 手札のSpace操作は対象選択状態へ入り、枠・照準で対象を示す。操作説明用ボタン・常設ヒント・ドラッグ状態の文章は描画しない。カードクリックは効果確認、手札選択待ちは選択／解除として扱う。
- `src/useCardDrag.ts`: Pointer Events・pointer captureによるマウス/タッチ/ペン共通のドラッグ、ヒット判定、キャンセル
- `src/CardPopover.tsx`: カード効果とCO操作のポップアップ。画面内への位置調整、外側クリック・Escで閉じる操作。
- `src/GameChoices.tsx` / `src/choices.css`: 手番外を含むサーバー指定の選択画面、追加対象・数値・市民能力の設定、手札からのCOと不要役職の返却、キーボードフォーカス管理。
- `src/CardFace.tsx`: 卓上の手札・場・捨て札確認、効果元、設置防御候補と選択ポップアップで共有するカード表面・マーク描画。見た目の定義を二重に持たない。
- `src/TableCards.tsx` / `src/table-selection.css`: 個別条件を持つ設置カード・期間効果の表面、場の効果順序選択、山札／捨て札の候補列。効果説明はホバー表示し、単一選択に番号を付けない。
- `src/fixed-table.css`: PC向け1400×900の固定配置を定義する。`GameBoard` の `ResizeObserver` が利用可能な領域に収まる倍率だけを更新し、選択欄や設置カードの増減で卓のサイズを変えない。候補列内のスクロールと卓全体のスクロールを分離する。
- `src/game/card-display.ts`: 手札・ドラッグ中のカードに現在の攻撃値を表示する。エンジンの `attackBaseValue` と `attackValue` を共用し、使用時に手札／捨て札へ移るカード自身も考慮する。対象の防御・軽減前の表示であり、ダメージ確定値ではない。
- `src/game/choice-presentation.ts`: サーバーが回答者向けの結果プレビューを生成する。通常ダメージの軽減計算はエンジンと共有し、選択内部のtask/cards/queueをブラウザへ渡さない。
- `server/game-view.ts`: 本人用の選択肢・プレビューと公開済み効果元を配信し、他人の手札・伏せ役職・選択内容を除外する。
- `src/game/v02.test.ts`: カード枚数、ダメージ計算、設置防御、CO/強制開示、遅延・期限、交換・投票・死亡時誘発等の回帰検証。
- `src/battle-interaction.test.ts` / `src/GameBoard.interaction.test.tsx`: 使用先ごとのコマンド、ホバー、ロックオン、確定・キャンセル、CO、非公開情報と二重送信の検証
- `src/battle-layout.ts`: 自分を基準とした席順と人数別の配置、手札の扇状配置
- `src/battle-layout.test.ts`: 全人数・全視点の席順、死亡者の席保持、手札上限超過時の配置、非公開情報の表示境界

React/Vite/TypeScriptで構築する。ゲームエンジンはDOMやReactに依存させず、単体テスト可能にする。

## 状態更新

UIはユーザー操作をWebSocketコマンドとしてサーバーへ渡す。サーバーは接続に紐づいたプレイヤーを特定し、ゲームエンジンで入力を検証する。成功した状態を、接続中の全プレイヤーへリアルタイム配信する。

ゲーム状態の正本はサーバーだけが保持する。配信前にプレイヤーごとの表示状態を生成し、他人の手札は枚数だけ、伏せ役職は存在だけを送る。本人限定ログも対象プレイヤーだけへ送る。

## 効果処理

`GameState.queue` に成立済み効果を保持し、`pendingChoice` が発生するまで解決する。`RESOLVE_CHOICE` は選択ID・回答者・枚数・候補・対象を検証してから処理を再開する。選択画面を跨いでもキューはサーバーに残り、再接続で自分の選択へ復帰できる。

全員対象は使用者を起点とした席順、投票回答は固定親基準の席順。ヒットごとに `ATTACK → DEFEND → DAMAGE → RESCUE` を解決し、対象死亡で残りヒットを停止する。成立済み効果は発動者死亡後も続行する。

`effects` は所有者・対象・所有者のターン回数・開始/終了期限を保持する。常時設置は無期限、大きな石は現在のグローバルターン終了まで。期限の複数効果は `ORDER` 選択から `EXPIRE` を指定順に積み、解決後に `NEXT_TURN` を処理する。残虐な猶予・回復予約は所有者死亡で失効させない。

`ACTION` が元の行動と継続タスクを保持し、固定親順で `INTERRUPT` を確認してからタスクを解決する。`REDIRECT` は対象と裏向き手札候補を更新し、カウンターγは発言の使用者・対象を交換する。回答済み候補UIDを記録し、同じ候補の再提示ループを防ぐ。手札使用制限は通常使用と手札誘発に共通で適用する。

`DAMAGE_RESPONSE` は実ダメージ前の手札誘発。軽減計算は `normalDamageAmount` と共用。HPへ適用した量をturnDamage／turnSelfLossへ記録し、白夜の斬撃の次ヒットを生成する。死亡時はdeathGenerationsを増やし、赤ずきんのREVIVE後も同じ連続攻撃を再開させない。通常回復タスクは死亡者を復活させない。

`extraTurns` は使用者の追加ターン予約、`extraTurn/extraFatal` は実行中の追加ターンを表す。追加ターンでは席順とフェーズを進めず、開始・終了期限と補充は処理する。通常ターンへ戻る際のフェーズ周期は2フェーズごとの昼夜反転。`winnerIds` は通常勝者からvictoryLinksを推移的に解決した共有勝者一覧で、死亡だけではリンクを削除しない。

配信時に山札は枚数だけを公開し、queue・votes・pendingChoiceの内部task/tasks/cardsは除外する。選択肢は回答者だけに配信する。CPUにも同じ秘匿済み状態を渡し、現在の手番より選択待ちの回答者を優先して動かす。

UIの選択状態は `useChoiceSelection` で管理し、選択ID・接続状態・エラーの切り替わりで初期化する。TRADE/VOTE/DEMAND/RESCUEは既存の手札を直接選択する。GUARD/SEER/ASSASSINとVOTEの対象は席／役職、ORDERは場の効果カードから選ぶ。DRAW/RECOVERは `CardSpread` の卓内候補列を使い、全面モーダルにしない。DEFENSEは `DefenseCards` を自分の場に展開し、`DefenseContext` で効果元と山札付近の確定／スキップを表示する。追加対象や数値も席／ボタンで選ぶ。案内と結果は卓内の固定領域に表示し、選択順・枚数上限・再クリック解除・送信ロックを共通化する。

`Player.shield` はCPUの簡易評価で参照する互換値として残るが、HP付近には表示しない。実際の防御は従来どおり1ヒットごとの設置カード発動。被弾演出はHPの減少だけで発生し、防御カード消費だけでは発生しない。

`sourceCard` は公開済みの効果元を示す表示専用情報。多段階選択・反撃・死亡時誘発・遅延予約へ引き継ぐが、ルール上の `card`（設置カードの移動や発言無効化等）とは分離する。`presentation` は配信時に回答者だけへ生成し、選択ごとの結果と不使用時の結果を示す。防御は今回の1ヒットに限定したHP予測であり、後続ヒットや死亡時の再選択を先読みしない。

## 接続と再接続

部屋作成・参加時に推測困難な再接続トークンを発行する。ブラウザには部屋コードとトークンだけを保存し、ゲーム状態や秘密情報は保存しない。再読み込み後はトークンをサーバーへ提示し、自分用の最新状態を取得する。

現段階の部屋はサーバーメモリ上に保持する。サーバープロセス再起動をまたぐ永続化は、配備環境決定後に追加する。

## テストモード

1人でゲームを作成した場合、ゲーム状態の `mode` を `TEST` とする。ゲームエンジンは通常対戦と同じ処理を使用するが、最後の生存者による勝利判定だけを行わない。2人以上の場合は `NORMAL` とする。

CPU対戦では `START_GAME.cpuCount` をサーバーで整数0〜5・人間1人の条件で検証し、CPUメンバーを追加してから通常ゲームを作成する。CPUの役割は `LobbyPlayer.isCpu` で伝え、ブラウザからCPUを操作する経路は設けない。CPUには再接続を認めず、手札と伏せ役職は通常の相手と同様に秘匿する。
