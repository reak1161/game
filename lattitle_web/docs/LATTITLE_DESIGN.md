## 1. 目的と版の区分

ラティトルは、4×4の盤面で4人の仲間を動かしながら、行動ゲージがたまった仲間にコマンドを指示して敵を倒すリアルタイム戦闘ゲームである。

| レガシーWeb版 | オリジナルの見た目とルールをブラウザで体験できる版。`D:/programming/game/lattitle_web/legacy/` | Web実行に必要な互換修正のみ |
| 製品版 | 元のリアルタイム戦闘ルールを基に、操作性、視認性、内容を磨く版 | レガシー版とは別に開発する |

製品版の方針はユーザー確認済みの「元のルールを磨く」。以下では、**現行仕様**はコードから確認した動作、**製品版方針**は今後実装する設計、**要決定**は現時点で確定していない事項を示す。

## 2. 現行レガシー版のゲーム仕様

### 2.1 ゲーム進行

1. タイトル画面の「ゲームプレイ」を押す。
2. 固定された4人のプレイヤーと敵「へび」で戦闘を開始する。
3. プレイヤーは仲間を選択し、盤面上をドラッグして移動経路を指定する。
4. 行動ゲージが1000以上になった仲間は、4枠のコマンドから行動する。
5. 敵もゲージで行動し、予告されたマスに攻撃する。
6. 敵が全滅したらクリア、仲間が全滅したらゲームオーバー。判定から約5秒後に結果画面へ移る。

レガシー版にはタイトルへ戻る操作、再戦、セーブ、ゲーム設定画面は実装されていない。タイトルの設定ボタンはコメントアウトされている。

### 2.2 画面・入力

| 画面 | 現行仕様 |
| --- | --- |
| タイトル | ゲーム名と「ゲームプレイ」ボタン |
| 戦闘 | 左に敵と4×4盤面、右にプレイヤー情報またはアイテム欄。選択中の仲間のコマンドを盤面上部に表示 |
| 結果 | 「ゲームクリア」または「ゲームオーバー」を表示 |

- 基準解像度は1440×810、更新目標は90 FPS。
- マウスの左ボタンで仲間を選択する。同じ操作で盤面をなぞると経路を描き、ボタンを離すと移動を予約する。
- 戦闘中の右側タブで「プレイヤー」と「アイテム」を切り替える。
- アイテムを選んだ後、行動可能な仲間の「アイテム」コマンドで使用する。
- F1でフルスクリーン、F2またはEscで通常表示に戻す。

### 2.3 盤面と移動

- 盤面は4列×4行。座標は左上を `(0,0)` とし、`x,y` はそれぞれ `0..3`。
- 初期配置は4人が `(0,0)`, `(1,1)`, `(2,2)`, `(3,3)`。敵は盤面外に表示され、列ごとの当たり判定を持つ。
- ドラッグで通過したマスを順に経路へ追加する。既に通ったマスへ戻ると、その先の経路を消す。
- 指を離した時点の終点に、別の仲間の予約がなければ移動を確定する。占有判定は現在位置ではなく予約された目的地で管理する。
- 移動所要フレームの式は `fps × 2点間距離 × 5 × (1/5)^(Spd/100)`。防御時は移動速度補正が掛かる。
- 移動中は行動ゲージの増加に `Itg_Spd / 100` の補正が掛かる。

### 2.4 行動ゲージとコマンド

- 行動ゲージの上限目安は1000。ゲージが1000以上の仲間だけコマンドを押せる。
- ゲージをためる基準フレーム数は `fps × 20 × (1/2)^(Itg/100)`。1フレームあたり `1000 / 基準フレーム数` 増加する。
- 使用可能なコマンド種別は攻撃、防御、魔法、アイテム。データにはスキル種別の分岐もあるが、処理は未実装。
- 攻撃と魔法にはチャージ時間を持つものがある。チャージ終了後に行動が実行され、ゲージを消費する。
- 防御は軽減率、固定軽減量、移動速度補正を設定し、行動ゲージを0にする。
- 敵は同様にゲージをため、行動後のクールダウン中は増加速度が1/10になる。敵の技は予告マス、表示までの時間、予備動作時間を持つ。

### 2.5 ダメージ、属性、状態

- 物理攻撃の初期値は `floor(22 × (攻撃値 + 20) / (防御値 + 20))`。技威力、属性、属性一致、隊列・ガード、乱数などを順に適用する。
- 属性一致の補正は1.5倍。乱数は0.85～1.00。属性の相性処理は `element.py` にある。
- 魔法はMPを使い、残MPと魔法効率の補正を受ける。魔法効率の係数計算はWeb版でNumPyを使わない同等の四則演算へ置き換えた。
- HPは実値と表示値を分け、ゲージを徐々に変動させる。MPには自動回復がある。
- 状態・追加効果として、移動不能、行動不能、滑り、凍傷、凍結、炎上、速度上昇などの処理が存在する。
- 敵の攻撃は予告マスと仲間の四捨五入した位置が一致した場合に命中する。敵ごとの行動とパッシブは個別のPythonモジュールで定義されている。

### 2.6 現行コンテンツとデータ

| 種類 | 保存先 | 現行データ |
| --- | --- | --- |
| プレイヤー | `data_list/players/player_*/player_*.csv` | 5件。通常戦闘では4人を固定選択 |
| 敵 | `data_list/enemies/enemy_*/enemy_*.csv` | 3件。通常戦闘では「へび」1体を固定選択 |
| 敵固有行動・パッシブ | 各敵フォルダの `action.py`, `passive.py` | 敵ごとの挙動 |
| アイテム | `lattitle_main.py` の初期配列と `items.py` | ポーション、マナポーション、ハヤブサの羽 |
| 画像・フォント | `data_list/images/`, `data_list/fonts/` など | UI、キャラクター、状態表示 |

CSVは行位置に意味がある現行形式で、プレイヤーは基本能力・属性・4コマンド、敵は基本能力・当たり判定列・パッシブ・行動の重みを順番に保持する。製品版ではこの行位置依存を廃し、名前付きフィールドへ変換する。

## 3. レガシーWeb版の技術設計

### 3.1 構成と起動

```text
lattitle_web/
  index.html                 版を選ぶ入口
  README.md                  起動・ビルド方法
  legacy/
    main.py                  ブラウザ用エントリーポイント
    lattitle_main.py         元のメインループをWeb対応
    *.py                     元ゲームの処理
    data_list/               CSV、画像、フォント
    build/web/               Pygbag生成物（Git対象外）
```

ブラウザ実行にはPygbag 0.9.3を使う。`legacy/main.py` がPygameを先に読み込み、元の処理を非同期ループとして起動する。毎フレーム `asyncio.sleep(0)` でブラウザへ制御を返す。生成物は静的サイトとして配布できる。外部公開先は未決定。

### 3.2 オリジナルとの差分と保存原則

レガシー版はオリジナルを複製したスナップショットとし、ルールや演出の改善を混ぜない。Web上で実行するため、画面作成をPygame初期化後に移動し、NumPy依存を四則演算へ置換した。再生処理が元から無効だったMP3はWeb用コピーから除外した。終了イベントはブラウザ側のループを返して終了する。

今後Web互換性の不具合を直す場合は、この節に差分と理由を追記する。製品版の変更は別の実装に加え、レガシー版へ逆流させない。

### 3.3 確認済み範囲と制約

- ローカルブラウザで、入口 → タイトル → 戦闘 → 仲間の選択 → コマンド表示を確認済み。
- クリア・敗北までの通しプレイ、各技・各状態効果、スマートフォン操作、全ブラウザでの動作は未確認。
- 初回起動時は画面をクリックしてWeb側の実行を開始する。
- 現行UIはマウス操作と固定比率を前提としている。
- 元コードにある未実装部分や既知でない不具合は、レガシーの保存と製品版の改善対象を分けて扱う。

## 4. 製品版の設計方針

### 4.1 継承する体験

**製品版方針:** 4×4盤面、仲間4人、経路指定による移動、移動と行動ゲージの兼ね合い、コマンド選択、敵の攻撃予告と回避、属性・状態効果という戦闘の核を維持する。レガシー版を比較基準として、変更したルールは仕様と理由を記録する。

### 4.2 製品版で改善する項目

1. **操作:** マウスとタッチの両方で経路指定とコマンド選択を確実に行えるようにする。移動の確定・キャンセルを視覚的に示す。
2. **戦闘の読みやすさ:** 行動可能な仲間、敵の予告範囲と残り時間、状態効果、攻撃が当たる列を常時把握できるようにする。
3. **進行:** 再戦、タイトルへの復帰、一時停止、音量設定、操作説明を用意する。
4. **データとロジック:** 戦闘計算を描画から分離し、データを明示的な形式に移す。乱数を制御できるようにして戦闘を再現・検証する。
5. **内容:** プレイヤー・敵・技・アイテムを増やす際も既存戦闘のバランスを追える仕組みにする。
6. **配布:** レガシー版と製品版を別URLで提供し、入口から両方へ進めるようにする。

これらは実装方針であり、個々のUI配置・数値・追加コンテンツは未確定。

### 4.3 推奨アーキテクチャ

```text
製品版アプリ
  画面・入力層      タイトル、戦闘UI、タッチ／マウス操作
  戦闘エンジン層    固定時間更新、移動、ゲージ、行動、状態、勝敗
  コンテンツ層      キャラクター、敵、技、アイテム、画像、音
  保存・設定層      設定、進行状況（採用範囲は要決定）
```

戦闘エンジンは描画APIやDOMに依存させず、入力イベントと経過時間を受け取り、次のゲーム状態と表示イベントを返す。これによりレガシーとの挙動比較と自動テストを可能にする。ブラウザ向けの具体的な言語・描画方式は、戦闘仕様の確定後に選ぶ。

## 5. 製品版プロトタイプの実装状況（2026-09-22）

`D:/programming/game/lattitle_web/remake/` に、ライブラリの追加インストールが不要な静的Webアプリを作成した。`data.js` はオリジナルCSVから4人と「へび」の能力・技・アイテムを転記したデータ、`engine.js` は描画に依存しない戦闘処理、`app.js` と `styles.css` は画面と入力を担当する。

未実装・要検証: 敵固有のパッシブ、他2種類の敵、効果全般の完全再現、原作と数式・フレーム単位で一致する検証、タッチ端末での実機操作、勝敗までの通しプレイ。現在の実装を完成版とは扱わない。
