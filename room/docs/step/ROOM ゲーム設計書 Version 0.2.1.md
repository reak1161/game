# ROOM ゲーム設計書
## Version 0.2.1

> Game Title: **ROOM**  
> Full Title: **Royale Of Outlaws & Monsters**  
> Version: **0.2.1**  
> Status: Draft / 拡張前提

---

# 1. Version 0.2.1 更新概要

Version 0.2.1では、主に以下を追加・変更する。

- マッピングシステムを追加
- ミニマップ表示モード切替を追加
- ショップを実装
- ショップ商品を5枠表示
- 現時点ではアイテムのみ販売
- 商品重複を許可
- 情報取得・強調対象・敵方向の方向表示を追加
- 通常モンスターの同時存在上限を100体に設定
- プレイヤー不在エリアのモンスターを自動消滅
- モンスタースポーン位置をプレイヤー周辺へ重点化

---

# 2. マッピング

100×100マップでは、すべての情報を最初から表示しない。

プレイヤーが実際に発見・確認した情報を、

**マッピング済み情報**

として記録する。

---

# 3. 未発見情報

以下のような情報は、未発見状態ではマップへ表示しない。

```text
ショップ
ボス関連地点
その他重要地点
特殊オブジェクト
```

プレイヤーがその情報を確認することで、マップへ登録される。

---

# 4. ショップのマッピング

ショップは段階的に情報を取得できる。

例：

```text
ショップ未発見
→ マップに表示されない

ショップを発見
→ ショップ位置をマップへ登録

ショップの商品を確認
→ 商品情報もマッピング
```

一度マッピングした情報は、マップから後から確認できるようにする。

---

# 5. ボス情報のマッピング

ボス出現地点やボス関連情報についても、マッピングシステムの対象とする。

ボス固有の出現予告など、ゲーム側から明示的に通知された情報については、その時点でマッピング済みとして扱うことができる。

詳細な公開条件はボスごとに設定可能とする。

---

# 6. ミニマップ

ミニマップには表示モードを用意する。

ミニマップ付近に切替ボタンを配置する。

---

# 7. ミニマップ表示モード

ボタンを押すたび、

```text
付近表示
↓
全体表示
↓
最小化
↓
付近表示
...
```

と順番に切り替える。

---

# 8. 付近表示

```text
モード：付近表示
```

プレイヤー周辺を拡大して表示する。

主に戦闘・探索中の周辺状況確認に使用する。

---

# 9. 全体表示

```text
モード：全体表示
```

100×100マップ全体をミニマップ領域内へ縮小表示する。

マッピング済みの、

```text
ショップ
ボス地点
重要地点
その他情報
```

を確認できる。

---

# 10. 最小化

```text
モード：最小化
```

ミニマップ本体を非表示、または最小サイズへ変更する。

ただし、

**表示モード切替ボタンは常に操作可能な状態で残す。**

ミニマップと一緒に切替操作まで完全に消さない。

---

# 11. ショップ実装

ショップを実際にゲーム内へ実装する。

既存操作仕様：

```text
ショップから距離1.6以内
→ Fキーで開く
```

ショップUI表示中もゲームは停止しない。

---

# 12. ショップ距離

```text
0～1.6
→ Fでショップを開ける

1.6～3
→ すでに開いているショップUIは維持

3以上
→ ショップUIを自動で閉じる
```

プレイヤーはショップUI表示中も移動可能。

---

# 13. ショップの商品枠

ショップの商品数：

```text
5枠
```

とする。

---

# 14. 現在の商品カテゴリ

現時点ではショップ販売対象として実装されているのは、

```text
アイテム
```

のみ。

そのため、Version 0.2.1では5枠すべてをアイテムから抽選する。

---

# 15. 商品の重複

現時点では、

**同じアイテムが複数枠へ出現してもよい。**

例：

```text
1：すばやさのポーションS
2：かいふくポーションS
3：すばやさのポーションS
4：こうげきのポーションS
5：かいふくポーションS
```

のようなラインナップも有効。

---

# 16. 将来のショップ拡張

将来的にはショップ商品として、

```text
アイテム
アビリティ
スキル
バフ
回復
特殊商品
```

等を追加可能にする。

カテゴリごとの抽選確率を設定可能な構造とする。

現時点：

```text
Item：100%
```

---

# 17. ショップ在庫

既存仕様通り、

**ショップ在庫は全プレイヤー共有**

とする。

あるプレイヤーが商品を購入した場合、他プレイヤーから見てもその在庫は減少する。

---

# 18. 方向インジケーター

重要情報が現在の画面外に存在する場合でも、

**その方向が分かるようにする。**

画面端へ対象方向を示すインジケーターを表示する。

---

# 19. 方向表示の対象

例：

```text
新しく発見したショップ
ボス出現地点
強調表示された目標
敵アウトロー
特殊モンスター
その他重要オブジェクト
```

---

# 20. 画面上の方向表示

対象が画面外の場合、

```text
対象が存在する方向の画面端
```

へ矢印・アイコン等を表示する。

対象が画面内へ入った場合は、通常の対象表示へ切り替える。

---

# 21. ミニマップ上の方向表示

付近表示等で、対象が現在のミニマップ表示範囲外にいる場合も、

**ミニマップの端へ対象方向を示すマーカーを表示する。**

全体表示で対象位置そのものを表示できる場合は、通常アイコンを使用する。

---

# 22. 情報取得時の強調

新しい情報を取得した場合、

```text
新ショップ発見
ボス地点発見
重要地点マッピング
```

等を一時的に強調表示できるようにする。

例：

```text
通知
+
方向インジケーター
```

を数秒表示する。

これにより、情報を取得しても位置を見失いにくくする。

---

# 23. モンスター同時存在上限

マップ上に同時に存在できる通常モンスター数は、

```text
100体
```

までとする。

---

# 24. 上限到達時

通常モンスターが100体存在している場合、

**新しい通常モンスターの生成を停止・抑制する。**

既存モンスターが消滅・撃破され、100体未満になった後に再び生成可能になる。

---

# 25. ボスと存在上限

ボスは、

```text
通常モンスター100体上限
```

には含めない。

そのため、

```text
通常モンスター100体
+
ボス
```

の同時存在も可能。

---

# 26. モンスターの有効範囲

通常モンスターについて、

プレイヤーの「付近」を、

```text
半径40程度
```

とする。

現時点では、

```text
半径40
```

を基準値として使用する。

---

# 27. 通常モンスターのデスポーン

ボス以外のモンスターが、

**全プレイヤーから半径40より遠い状態**

になった場合、デスポーン待機を開始する。

---

# 28. デスポーン時間

プレイヤーが付近に存在しない状態が、

```text
3秒
```

継続した場合、その通常モンスターは消滅する。

---

# 29. デスポーンキャンセル

デスポーン待機中の3秒以内に、

いずれかのプレイヤーが再び、

```text
半径40以内
```

へ入った場合、

**デスポーン処理をキャンセルする。**

---

# 30. ボスのデスポーン

ボスはプレイヤーが付近にいなくなっても、

**自動消滅しない。**

通常モンスター専用の3秒デスポーンルールは適用しない。

---

# 31. モンスタースポーン位置

通常モンスターのスポーン位置は、プレイヤー周辺を優先する。

全スポーンの、

```text
90%
```

は、

**いずれかのプレイヤーから半径40以内**

の有効地点へ生成する。

---

# 32. 残り10%のスポーン

残り、

```text
10%
```

については、半径40の外側を含めたマップ上の有効地点へ生成可能とする。

これにより、

```text
プレイヤー周辺
→ 高密度

遠方
→ 少数存在
```

という分布を作る。

---

# 33. 複数プレイヤー時のスポーン判定

複数プレイヤーが存在する場合、

**全プレイヤーの半径40範囲**

をスポーン候補として扱う。

特定プレイヤーの周辺だけに偏らないよう、候補プレイヤーや候補地点を適切に抽選する。

---

# 34. スポーンとデスポーンの目的

100×100マップ全域にモンスターを常駐させるのではなく、

```text
プレイヤーが活動している場所
```

を中心にモンスターを生成・維持する。

これにより、

- プレイヤー周辺のモンスター密度を維持
- 誰もいない場所の不要なモンスターを削除
- サーバー・クライアント負荷を軽減
- 広域マップでも戦闘密度を確保

する。
