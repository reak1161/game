# ROOM ゲーム設計書
## Version 0.1.16

> Game Title: **ROOM**  
> Full Title: **Royale Of Outlaws & Monsters**  
> Version: **0.1.16**  
> Status: Draft / 拡張前提

# 1. Version 0.1.16 更新概要

Version 0.1.16では、主に以下を追加・変更する。

- プレイヤー向け説明文と内部仕様を分離
- 属性は任意項目であることを再明確化
- ゲーム内ウィンドウのスクロールバーを独自デザイン化
- 一覧系ウィンドウの閉じる操作を改善
- クリティカルシステムを追加
- 新アビリティ「アイスストーム」を追加
- 「攻撃力＋○%」表記を「ダメージ＋○%」へ変更
- ダメージ補正の適用対象を明確化

---

# 2. プレイヤー向け説明文

ゲーム内でプレイヤーへ表示するスキル・アビリティ説明文は、内部仕様をそのまま表示しない。

プレイヤーがゲームを理解するために必要な情報へ簡略化する。

基本的な表示対象：

```text
効果内容
ダメージ / 回復量
CD
持続時間
距離 / 射程
範囲
発動条件
スタック数や回数
```

必要以上に内部実装を説明しない。

---

# 3. プレイヤー向けに表示しない情報

以下のような情報は、原則として内部仕様としてのみ保持する。

```text
当たり判定の細かな形状
ヒットボックス端からの正確な計算方法
内部座標計算
配置アルゴリズム
攻撃判定生成方法
実装上の補正値
```

例えば、

```text
プレイヤーヒットボックス前端から0.5先を起点とする
```

のような仕様を、ゲーム内説明文へそのまま書く必要はない。

プレイヤー向けには、

```text
前方3.2
半径0.5
```

程度の情報でよい。

---

# 4. 内部仕様と表示文の分離

スキル・アビリティ定義は、

```text
内部仕様
プレイヤー向け説明文
```

を分離して管理できる構造とする。

バランス値そのものは可能な限り共通データを参照し、説明文との数値不一致を防ぐ。

---

# 5. 属性の扱い

すべてのスキル・アビリティに属性が存在するわけではない。

属性は、

**任意のメタデータ**

として扱う。

属性を持つ場合のみ、

```text
🔥 火
💧 水
⚡ 雷
❄ 氷
光
闇
```

等を設定する。

属性を持たないスキル・アビリティに対して、無理に「無属性」という属性を付与する必要はない。

例：

```text
ダッシュ
ダブルダッシュ
トリプルショット
```

などは属性なしとして扱える。

---

# 6. ゲーム外一覧画面の属性表示

アビリティ・スキル一覧画面でも、属性は任意表示。

```text
属性あり
→ 属性アイコン / 属性名を表示

属性なし
→ 属性欄を非表示
```

とする。

---

# 7. スクロールバーのデザイン

モンスター一覧、アビリティ一覧、アウトロー一覧等のスクロール可能UIでは、

**ブラウザ標準のスクロールバーをそのまま使用しない。**

ROOMのUIデザインに合わせて独自デザインを適用する。

---

# 8. スクロールバーのデザイン方針

基本方針：

```text
細め
低彩度
UI背景になじむ
つまみ部分は判別可能
過度に目立たせない
```

ゲーム画面全体から浮かないデザインを目指す。

Web実装ではCSS等によるスクロールバーのカスタマイズを行う。

---

# 9. 一覧ウィンドウの閉じる操作

以下のような大きなウィンドウでは、

```text
モンスター一覧
アビリティ一覧
アウトロー一覧
その他図鑑・情報画面
```

スクロール位置に関係なく閉じる操作を行えるようにする。

---

# 10. 固定ヘッダー

一覧ウィンドウでは、

**ヘッダー部分を固定表示**

する。

ヘッダー右上に、

```text
×
```

の閉じるボタンを配置する。

本文部分のみスクロールさせる。

---

# 11. Escキー

一覧・情報系ウィンドウは、

```text
Esc
```

でも閉じられるようにする。

これにより、スクロール位置やカーソル位置に依存せず即座にゲーム画面へ戻れる。

---

# 12. クリティカル

新しい共通戦闘システムとして、

**クリティカル**

を追加する。

---

# 13. デフォルトクリティカル率

アウトローの基本クリティカル率：

```text
3%
```

とする。

個別能力によって増減可能。

---

# 14. クリティカルダメージ倍率

デフォルト：

```text
1.5倍
```

とする。

例：

```text
通常ダメージ：20

クリティカル
→ 30ダメージ
```

---

# 15. クリティカルと防御バフ

クリティカル攻撃は、

**対象の防御系バフを無視する。**

例：

```text
基礎ダメージ：100
対象：被ダメージ軽減+20%
```

通常攻撃：

```text
100
→ 20%軽減
→ 80ダメージ
```

クリティカル：

```text
100 × 1.5
→ 防御バフを無視
→ 150ダメージ
```

---

# 16. クリティカルの視覚表現

クリティカル発生時は、通常ダメージと明確に区別できる表示を行う。

候補：

```text
ダメージ文字色を変更
文字サイズを少し大きくする
軽い強調アニメーション
```

通常ヒットとの違いが瞬時に分かることを優先する。

---

# 17. クリティカルSE

将来的にはクリティカル専用SEを用意することを想定する。

現時点ではゲーム全体のサウンド実装が未成熟なため、

```text
クリティカル専用SE
→ 後回し
```

とする。

---

# 18. クリティカルの拡張性

今後、以下のようなクリティカル関連能力を追加できる構造にする。

```text
クリティカル率+○%
クリティカル倍率+○
特定条件で確定クリティカル
クリティカル時に追加効果
クリティカル時に状態異常付与
クリティカル時に回復
```

そのため、クリティカル率・倍率等を固定値としてハードコードしない。

---

# 19. 新アビリティ「アイスストーム」

```text
名称：アイスストーム
条件：氷属性アビリティを3つ所持
```

自身の周囲に多数の氷粒を展開し、回転させる氷属性アビリティ。

---

# 20. アイスストームの氷粒

氷粒総数：

```text
30個
```

1個あたりのサイズ：

```text
0.2
```

氷粒は3層に分けて配置する。

---

# 21. アイスストームの3層構造

各層の軌道半径：

```text
第1層：0.8
第2層：1.3
第3層：1.8
```

氷粒数は半径に合わせて分配する。

現時点の分配：

```text
第1層：6個
第2層：10個
第3層：14個

合計：30個
```

---

# 22. アイスストームの配置

第1層と第3層は同系統の角度配置とする。

第2層は、

**氷粒間隔の半分程度、角度をずらして配置する。**

これにより各層の粒が一直線に重ならないようにする。

概念：

```text
第1層：●   ●   ●   ●
第2層：  ●   ●   ●   ●
第3層：●   ●   ●   ●
```

---

# 23. アイスストームの回転

各層はプレイヤーを中心に、

```text
毎秒240°
```

で回転する。

---

# 24. アイスストームのダメージ

氷粒が敵へ命中した場合、

```text
❄3ダメージ
```

を与える。

同一対象への連続ヒット間隔については、共通継続ヒットルールを使用するか個別設定するかTBD。

---

# 25. ダメージ補正の表記変更

従来使用していた、

```text
攻撃力+○%
```

という表記を、原則として、

```text
ダメージ+○%
```

へ変更する。

---

# 26. 「ダメージ+○%」の意味

単に、

```text
ダメージ+○%
```

と書かれている場合、

**アウトローが与えるダメージ全般**

を対象とする。

基本的には、

```text
通常攻撃
スキル
アビリティ
その他アウトロー自身が与えるダメージ
```

を含む。

通常攻撃だけを強化する意味ではない。

---

# 27. ダメージ補正の限定表記

特定の攻撃種類だけを強化する場合は、明確に別表記を使用する。

例：

```text
通常攻撃ダメージ+20%
スキルダメージ+15%
アビリティダメージ+10%
```

将来的に必要であれば、

```text
🔥火属性ダメージ+○%
❄氷属性ダメージ+○%
```

等も使用可能。

---

# 28. 既存効果の読み替え

これまで、

```text
攻撃力+○%
```

としていた効果で、特に限定条件が指定されていないものは、

```text
ダメージ+○%
```

として扱う。

該当例：

```text
こうげきのポーションS
エネルギーチャージ
帯電
滾る炎
ビーストフォルム
プレデターフォルム
プレデターフォルム撃破トークン
```

---

変更前：

```text

```

変更後：

```text
15秒間

```
