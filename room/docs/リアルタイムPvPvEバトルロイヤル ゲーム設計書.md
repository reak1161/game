# 1. このドキュメントについて

本ドキュメントは、ゲーム **ROOM（Royale Of Outlaws & Monsters）** のゲーム仕様および実装方針を管理するための設計書である。

ゲームは現在開発初期段階であり、キャラクター、アビリティ、Mob、マップ、アイテム等は今後大幅に追加されることを前提とする。

## 1.1 タイトル

ゲームタイトル：

```text
ROOM
```

正式名称：

```text
Royale Of Outlaws & Monsters
```

略称そのものが英単語として自然に読めることを意識している。

タイトルの意味としては、

- Royale：最後の1人になるまで戦うバトルロイヤル要素
- Outlaws：プレイヤーキャラクターたち
- Monsters：マップ上に存在する多数のMob / PvE要素

を表す。

ロゴ・タイトル画面等では基本的に **ROOM** をメイン表記とし、必要に応じてサブタイトルとして `Royale Of Outlaws & Monsters` を併記する。

---

# 1.2 Codex向け重要事項

実装時は以下を厳守すること。

- 本ドキュメントで「確定」とされている仕様を優先する。
- `TBD`、`未確定` と記載されている部分を独断で確定しない。
- キャラクター、スキル、アビリティ、アイテム等をハードコードしすぎず、追加・変更しやすいデータ駆動設計を優先する。
- 数値は今後頻繁にバランス調整されるため、可能な限り設定データへ分離する。
- 属性ごとの処理を大量の `if` / `switch` で固定せず、タグやEffect等によって拡張可能な構造にする。
- UIとゲームロジックを可能な限り分離する。
- オンライン対戦を前提として、最終的なゲーム状態の正当性はサーバー側で管理できる構成を想定する。
- 未実装仕様について仮実装が必要な場合は、コード上で明確に `TODO` を残す。

# 2. ゲーム概要

**ROOM（Royale Of Outlaws & Monsters）** は、見下ろし型リアルタイムPvPvEバトルロイヤルゲームである。

以下の要素を組み合わせる。

- Vampire Survivors系のレベルアップ・ビルド構築
- PvP
- PvE
- バトルロイヤル
- ランダムマップ
- 探索
- ショップ
- ローグライト的なランダム成長

大量のMobを倒して経験値やコインを獲得しながらキャラクターを成長させ、同じマップ上に存在する他プレイヤーと戦う。

最終的に最後まで生存したプレイヤーが勝利する。

# 3. 基本ゲームループ

```text
キャラクター選択
        ↓
ゲーム開始
        ↓
Lv1アビリティ選択
        ↓
探索 / Mob討伐 / コイン獲得
        ↓
レベルアップ
        ↓
アビリティ・スキルによるビルド構築
        ↓
ショップ探索・購入
        ↓
他プレイヤーとのPvP
        ↓
10分経過後マップ縮小開始
        ↓
20分で最終エリア確定
        ↓
最後の1人になるまで戦闘
        ↓
勝利
```

# 4. 勝利条件

## 4.1 基本ルール

最後まで生存したプレイヤー1名が勝利する。

チーム戦については現時点では対象外。

## 4.2 試合時間

試合そのものに強制終了時間は設けない。

ただしマップ縮小によってプレイヤー同士の接触を促進する。

### 時間進行

| 経過時間 | 状態 |
|---|---|
| 0:00～5:00 | 復活可能期間 |
| 5:00～10:00 | 通常バトルロイヤル |
| 10:00 | マップ縮小開始 |
| 10:00～20:00 | 徐々にプレイ可能エリア縮小 |
| 20:00 | 最終エリア確定 |
| 20:00以降 | エリアは変化せず、最後の1人になるまで継続 |

---

# 5. 死亡・復活

## 5.1 最初の5分間

ゲーム開始から5分以内に死亡した場合、プレイヤーは復活できる。

### 復活時ペナルティ

- 所持コインを50%失う。
- 現在レベルは維持する。
- 現在レベル内の経験値進行度を0にする。

例：

```text
死亡前:
Lv5.5 相当

復活後:
Lv5.0 相当
```

つまりLv5からLv6へ進むための経験値のみ失う。

復活位置や復活待機時間はTBD。

# 6. 本死亡・ゴースト

5分経過後に死亡した場合、そのプレイヤーはバトルロイヤルから脱落する。

ただし試合から完全退出する必要はなく、以下から選択できる。

- 通常観戦
- ゴーストとして参加

## 6.1 ゴースト

ゴーストは生存プレイヤーに干渉可能。

### 基本性能

- 中型Mob程度の戦闘能力
- 移動可能
- 通常攻撃可能
- 生存プレイヤーへダメージを与えられる
- バトルロイヤルの勝者判定には復帰しない

# 7. 操作方法

## 7.1 基本操作

| キー / 入力 | 操作 |
|---|---|
| W | 上方向移動 |
| A | 左方向移動 |
| S | 下方向移動 |
| D | 右方向移動 |
| マウス | キャラクターの向き / 照準 |
| Q | スキル1 |
| E | スキル2 |
| Space | ダッシュ |
| M | 全体マップ |

## 7.2 前方の定義

キャラクターから見た「前方」は、

**キャラクター位置 → マウスカーソル位置**

の方向とする。

移動方向とは独立する。

そのため、

- 前進しながら横へ攻撃
- 後退しながら前方へ攻撃

等が可能。

├─ 通常攻撃タイプ
├─ パッシブ

## 8.1 通常攻撃タイプ

通常攻撃そのものはゲームの主火力にはしない。

# 9. パッシブ

## 9.1 定義

パッシブはキャラクター固有の受動能力。

ゲーム開始時から有効。

アビリティとは異なり、通常は試合中に取得するものではない。

例：

```text
移動速度が高くなるほどスキルCD回復速度が上昇
```

## 9.2 キャラクター選択画面

キャラクター選択時には最低限以下を表示する。

- キャラクター名
- 基礎ステータス
- 通常攻撃タイプ
- パッシブ
- 初期Qスキル
- キャラクターの特徴

固有E候補を事前公開するかはTBD。

---

# 10. スキル

## 10.1 定義

スキルはプレイヤーが能動的に使用する能力。

主に、

- Q
- E

で発動する。

基本的にはキャラクター固有。

ただしショップ等によって、ごくまれに以下が発生する可能性がある。

- キャラクター固有の別スキルへ変更
- 共通スキルへ変更

スキル交換は希少な要素とする。

頻繁には発生させない。

---

# 11. スキルのクールダウン

クールダウンは、

**スキルを発動した瞬間**

から開始する。

効果終了時からではない。

例：

```text
CD: 22秒
効果時間: 10秒

0秒:
スキル発動
CD開始

10秒:
効果終了

22秒:
再使用可能
```

CD回復速度上昇効果が存在する場合、実際の再使用可能時間は短縮される。

---

# 12. アビリティ

## 12.1 定義

アビリティは試合中に取得する能力。

以下を含む。

- 常時効果
- ステータスバフ
- 自動攻撃
- 条件発動効果
- ダッシュ強化
- スキルとの連携効果
- 特殊能力

例：

```text
自分の周囲を炎が回転し、接触した敵へダメージ
```

```text
ダッシュ使用時、周囲へ雷攻撃
```

---

# 13. アビリティの前提条件・派生

アビリティには上下関係・派生関係を設定できる。

上位アビリティには、取得条件となる下位アビリティが存在する場合がある。

例：

```text
ダッシュ
   ↓
迅雷
ダッシュ時に雷攻撃
   ↓
連鎖迅雷
迅雷が周囲の敵へ連鎖
```

「ダッシュ」を所持していない場合、「迅雷」は抽選候補に出現しない。

## 13.1 必須条件と関連は別概念

### 必須条件

条件を満たさない限り、絶対に抽選されない。

```text
requires:
- dash
```

### 関連

取得済み能力との関連性によって出現確率が上がる。

例：

```text
tags:
- dash
- lightning
- mobility
```

# 14. アビリティ抽選

通常レベルアップ時はアビリティ候補を3つ表示する。

基本的にはランダム。

ただし、現在のビルドに関連するアビリティをやや優遇する。

## 14.1 基本抽選案

各候補枠について、

```text
関連 / 上位候補 : 60%
無関係候補      : 40%
```

程度を基準とする。

確率は今後調整可能にする。

### 抽選処理イメージ

```text
候補枠1
 ↓
関連カテゴリ or その他カテゴリを抽選
 ↓
そのカテゴリ内からランダム

候補枠2
 ↓
同様

候補枠3
 ↓
同様
```

## 14.2 出現率補正

以下によって抽選確率が変化する場合がある。

- キャラクターパッシブ
- アビリティ
- バフ
- アイテム
- その他特殊効果

例：

```text
雷属性アビリティ出現率 +20%
```

抽選システムは固定ロジックにせず、Weight方式などによって外部から補正可能にする。

# 15. ダッシュ

## 15.1 基本仕様

ダッシュは全キャラクター共通で取得可能なアビリティ。

ただしゲーム開始時点では所持していない。

Lv1のアビリティ3択には、

**必ずダッシュを1枠含める。**

プレイヤーはダッシュを取得せず、他のアビリティを選択してもよい。

## 15.2 操作

```text
Space
```

で使用。

現在の移動方向へ短距離移動する。

距離、CD等はTBD。

## 15.3 派生

ダッシュ取得後のみ、ダッシュ関連アビリティが抽選可能になる。

例：

- ダッシュ時に雷攻撃
- ダッシュ後バリア
- ダッシュ回数増加
- ダッシュ距離増加

# 20. ショップ

マップ内には複数のショップが存在する。

ショップの位置はランダム生成。

## 20.1 商品数

各ショップ：

```text
5商品
```

## 20.2 商品共有

商品は全プレイヤー共通。

1つの商品を誰かが購入すると、その商品は売り切れる。

つまり先着購入制。

ショップはPvPが発生する重要地点の1つとなる。

## 20.3 商品カテゴリ

例：

- アビリティ
- アイテム
- バフ
- 回復
- スキル関連
- スキル交換
- その他特殊商品

商品カテゴリそのものもランダム。

## 20.4 カテゴリ抽選率

各商品ジャンルの出現率は設定値として管理できるようにする。

例：

```ts
shopCategoryWeights = {
  ability: 40,
  item: 30,
  buff: 20,
  skill: 5,
  special: 5
}
```

数値は仮。

コード変更を行わず調整できることが望ましい。

## 20.5 商品価格

基本的には、

**商品IDと価格を1対1で紐付ける。**

ランダム価格にはしない。

ゲーム管理者が明示的に価格を設定できるようにする。

## 20.6 ショップ更新

ゲーム開始から10分経過時にラインナップ更新。

同時にショップTierを上昇させる。

Tierによって高性能商品が出現可能になる。

```text

```

暫定計算式：

```text
CD回復速度補正
= 1 + (MovementSpeed - 1.0) × 0.5
```

例：

| 移動速度 | CD回復速度 |
|---:|---:|
| 1.0 | +0% |
| 1.2 | +10% |
| 1.5 | +25% |
| 2.0 | +50% |

負の移動速度補正時の扱い等はTBD。

# 47. 設計上の基本方針

本ゲームでは、

**「プレイヤーが毎試合異なるビルドを構築すること」**

を重要視する。

同じキャラクターであっても、

```text
アビリティ抽選
ショップ
スキル選択
マップ
他プレイヤー
Mob
```

によってプレイ内容が変化することを目標とする。

ただし完全な運任せにはせず、

- 関連アビリティ出現率補正
- 派生条件
- キャラクターパッシブ
- ショップ
- マップ探索

などによって、プレイヤー自身がある程度ビルドを制御できるようにする。

# 49. 最終目標

本ゲームは、

**大量のMobを倒して成長する爽快感**

と、

**他プレイヤーとのリアルタイムPvP**

および、

**ランダムマップを探索してビルドを作る戦略性**

を組み合わせたPvPvEバトルロイヤルを目標とする。

プレイヤーは単純に敵プレイヤーだけを追いかけるのではなく、

```text
Mobを狩る
ショップを探す
強Mobを狙う
ビルドを完成させる
危険地域へ行く
他プレイヤーを襲う
戦闘を避ける
```

といった判断を繰り返しながら、最後の1人を目指す。
