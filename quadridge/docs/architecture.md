# 実装構成

## 強化学習基盤 v0.1

- 正式なルールは `src/game-core/` に配置。形状、バッグ、配置、合法手、接続、判定、対局遷移、乱数、環境API、観測・行動変換を分離する。
- `src/engine.js` は互換用の再エクスポート。既存WebとRoomの呼び出し・状態形式を維持し、AI環境も同じ `play` を使う。
- `src/ai/` のランダムAI・シミュレータ・統計・CLIはNode.jsのみで動作する。コアはDOM・通信・Cloudflareに依存しない。
- 探索の複製は乱数位置までコピーする。判定勝ちの比較条件は `game-core/judgement.js` に集約する。APIの状態表現・用語・重要事項は `rl_foundation.md` を参照。
- 以下の旧バージョン記録にある `src/engine.js` の各処理は、現在 `src/game-core/` に移動済み。

## v0.7 構成

- `src/engine.js` の `scoreConnection` は自色の連結成分を列挙し、担当方向の両端までの残り距離が最小の成分を返す。`judgeBoard` は残り距離、代表経路の大きさ、総占有マス数の順で比較する。
- 判定情報は `judgment` として勝者、双方の値、代表経路、対岸へのガイドを持つ。Room の状態通知にも含め、ローカルとオンラインで同じ結果を描画する。
- `src/style.css`、`src/online.css`、`src/battle.css` は青灰色の共通パレットを使い、背景とパネルのグラデーションを使わない。

## v0.6 構成

- `src/engine.js` の `canStillConnect` は延長配置で合法的に獲得できる空きマスと自分のマスを探索し、対岸間の到達可能性を判定する。双方が到達不能なら、配置可能な形状が残っていても引き分けにする。
- パス時は延長配置でも配置可能な形状からリロールする。一方に合法配置がない場合は、候補が空のプレイヤーで手番を止めず、置けるプレイヤーへ進める。
- `src/battle-ui.js` と `src/battle.css` の一時ポップをローカルとオンラインで共用し、盤面中央のオーバーレイとして表示する。オンラインは前回受信した手数と延長配置状態との変化から表示する。

## v0.5 構成

- `src/battle-ui.js` は選択中候補のすぐ上へ回転操作を移し、候補の型名は画面から外す。型名は候補ボタンのアクセシブルな名前として残す。
- `src/battle.css` は盤面とゴール棒の寸法を同じ `--board-size` に揃え、対戦画面の背景を手番ごとの単色にする。
- 招待リンクのコピー操作は対戦開始前の待機画面に限る。対戦中のヘルプは小さな `?` から開ける。

## v0.4 構成

- `src/engine.js` は通常配置と延長配置を同じ状態遷移で扱う。通常配置可能な形状が尽きた時点で両者の候補を引き直し、以後は自分のマスへの重なりを認める。空きマスを少なくとも1つ埋める判定を入れる。
- `server/index.js` は延長配置状態を各クライアントに送る。配置可否は従来どおり Room の `play` で確定する。
- `src/battle-ui.js` と `src/battle.css` はローカルとオンラインの対戦画面を共通の盤面中心レイアウトにする。`src/help.js` に操作と延長配置の説明を置く。

## v0.3 構成

- `src/entry.js` は URL に応じてホーム・オンライン対戦 (`src/online.js`) とローカル2人対戦 (`src/local.js`) を読み込む。`src/identity.js` は表示名とルームコードの共通検証を行う。
- `server/index.js` の Worker は静的アセットと API を配信する。Lobby Durable Object はルームコードとランダム対戦の待機列を管理し、各 Room Durable Object は2人の接続、手札、盤面、手番、勝敗を保持する。
- Room は `src/engine.js` のルールで配置を検証し、確定した状態を WebSocket で配信する。クライアントはプレビューを描くが、配置結果を確定できない。相手の手札、バッグ、認証トークンは状態配信に含めない。
- プレイヤー ID と接続用トークンは別に生成する。同じ表示名でも別プレイヤーとして参加できる。ブラウザーの同一タブ内で接続情報を保持し、再読込時に復帰する。
- `wrangler.jsonc` が Worker、SQLite Durable Objects、静的アセット、SPA の URL、カスタムドメインを設定する。`npm run dev` でローカル Worker、`npm run deploy:check` で公開前のビルド確認を行う。

- `src/engine.js`：形状、バッグ、配置可能判定、パス・リロール、勝利経路、手番更新。DOM に依存しない純粋な対局処理。
- `src/local.js`：ローカル対戦の盤面と操作 UI。状態変更後に再描画する。
- 回転時は盤面の固定ゴーストを先に消して描画を確定させ、以前の向きの4マスだけを重ねて90度回転させる。マウス移動中も固定ゴーストを出さず、演出終了後に現在位置のゴーストを表示する。
- `src/style.css`：画面レイアウト、色、アニメーション、狭い画面への対応。
- `src/engine.test.js`：形状、バッグ、配置、接続のルール検証。
- Vite で静的アセットをビルドする。ローカル対戦はブラウザー内で状態を保持し、オンライン対戦は Room Durable Object に状態を保存する。

## 忘れてはならない事項

- プレイヤーの基準色は CSS 変数 `--player-blue: #417ab1` と `--player-red: #e83743`、ボタン・カード・情報パネルなどは `--ui-surface: #333844` に集約する。ゴールはプレイヤー基準色ではなく、盤面ブロックと同じ蒼 `#40bbd5`、朱 `#fb8678` を使う。ホームから対戦開始前までの `.online-shell` 背景は `#ced1d3` を維持する。盤面・ブロック・候補内のブロック・ゴーストは独立した色なので、これらの変更へ連動させない。
- 盤面セルはポインターを重ねただけでは色を変えない。配置ゴースト、配置不可、キーボードのフォーカス枠は維持する。
- 回転終了時は `rotating` を外す前に最終方向のゴーストを描画する。通常の背景色を一瞬挟まず、回転オーバーレイから確定ゴーストへ直接切り替える。
- 判定勝ちは残り距離、代表経路のマス数、総占有マス数の順で比較し、全条件が同じ場合だけ引き分ける。通常勝利と混同せず `judgment` の有無で表示を分ける。
- 判定の代表経路は両者とも表示し、不足部分は各プレイヤー色の点線で対岸方向へ示す。
- ホームと対戦画面の中立色は同じ青灰色パレットを使い、背景・パネル・ポップにグラデーションを戻さない。
- 候補の回転角度は枠ごとに保持する。選択中の候補だけを回し、選択していない候補は保存済みの向きで描画する。配置後は全枠の角度をリセットする。
- 延長配置の勝利可能性は相手のマスを通れず、新規マスを獲得できる合法配置だけを数える。両者が到達不能なら、手が残っていても引き分けにする。
- 候補が置けないときは延長配置中もパス・リロールする。片方の候補が空になっても、もう片方が置けるなら対局を続ける。
- 状態変化のポップは手数の進んだ時だけ表示し、再接続や再描画で繰り返さない。盤面操作を妨げない。
- ポップはゴール棒を含む配置領域ではなく、盤面の中央に重ねる。ブロックの配置操作は一時ポップ中も受け付ける。
- 招待リンクのコピー通知は相手を待っている間だけ表示し、対戦開始時に消す。対戦画面へ待機中の通知を引き継がない。
- 盤面とゴール棒を含む配置領域は、対戦画面の横幅に対して中央に置く。盤面の中心と画面の中心を揃える。

- ゴール棒の長さと位置は盤面外枠に合わせる。左右の文字を回転で逆さにしない。
- 招待リンクは2人目の参加前だけ表示する。対戦中に再び出さない。

- 延長配置でも相手のマスや盤面外に置けない。完全に自分のマスだけに重なる手は盤面が進まないため禁止する。表示上のゴーストとサーバー判定を一致させる。
- 既存ルームの古い対局状態には `extension` がないため、読み込み時は通常配置として扱う。

- オンライン対戦の配置と手番は必ず Room 側で検証し、クライアントから受け取った盤面や勝敗を採用しない。相手の手札・バッグ・接続トークンは送らない。
- ルームコードは公開してよい招待情報だが、プレイヤーの接続トークンは公開しない。同じ表示名での参加を拒否しない。
- 切断者や取り消した待機者をランダム対戦に組み込まない。復帰時はサーバーの状態を再取得する。
- 公開の前後にホーム、招待 URL、ルーム満員、ランダム対戦、2人の手番同期、切断復帰を確認する。

- 設計書 v0.1 / v0.2 の未決定事項は確定仕様として扱わない。引き分けは v0.4、先攻・候補端の入力・最小画面は `requirements.md` の判断を確認する。
- パス時はバッグを消費せず、盤面に配置可能な異なる形状を最大3つ抽選する。両者とも候補が置けないときはそれぞれパス・リロールし、置ける形状がある限り継続する。
- ルールを変える際は `engine.js`、画面ヘルプ、要件、テストを併せて確認する。
- 公開向けの変更は `patch_notes_public.md` に利用者の言葉で記載し、内部向け注釈を画面に出さない。
- 日本語ファイルは UTF-8 で保存する。PowerShell の文字列置換で編集しない。
- 他ゲームの作業中ファイルには触れない。
