## 強化学習基盤 v0.1

- seed再現、合法手列挙、局面複製、ランダムAI、Node.js単体での連続対局・統計・異常検出を提供する。
- 1000局以上の完走を完成条件とする。API・行動ID・観測表現と注意点は [利用方法](./rl_foundation.md) を参照。

v0.7 の追加要件は [0.7.md](./0.7.md) に従う。

## v0.7 ホーム・配色・判定勝ち

- 現在のプレイヤー基準色は蒼 `#417ab1`、朱 `#e83743`。ゴールは盤面ブロックと同じ蒼 `#40bbd5`、朱 `#fb8678` とする。ホームからルーム作成・参加・ランダム待機など対戦開始前までの背景は `#ced1d3`、ボタン・カード・情報パネル・入力欄・候補枠などの共通UI色は `#333844` とする。盤面とブロック本体、候補内のブロック、ゴーストの色は従来色を維持する。
- ホームはタイトル、短いキャッチコピー、プレイヤー名、対戦モードを中心にし、英字見出し、長い説明、常設の入力補足を外す。
- ホームと対戦画面は、グラデーションを使わない明るめの青灰色系ダークテーマで統一する。プレイヤーカラーと手番背景だけ蒼・朱を明確に使う。
- 延長配置の終了条件に達したら、各プレイヤーの自色連結成分から対岸までの残り距離が最小のものを代表経路とし、残り距離が小さい方を判定勝ちにする。
- 残り距離が同じ場合は、代表経路のマス数が多い方、総占有マス数が多い方の順で判定する。すべて同じ場合だけ引き分けにする。
- 判定時は双方の代表経路を明るくし、対岸までの不足部分を点線で示す。盤面中央に双方の残り距離と判定結果を簡潔に表示する。

v0.6 の追加要件は [0.6.md](./0.6.md) に従う。

## v0.6 終盤と状態通知

- 候補を置けずパスしてリロールした際は、盤面中央に「候補をリロール」を短時間表示する。延長配置開始時は「延長配置開始」を少し強く表示する。操作は妨げない。
- 延長配置中も、現在の候補をすべて置けなければパスし、延長配置の合法配置がある形状から候補をリロールする。片方に合法配置が残る限り、そのプレイヤーの手番で続ける。
- 延長配置の合法配置には新しい空きマスが少なくとも1マス必要。両者とも合法配置がない場合、または両者とも対岸へつなげる可能性が失われた場合に引き分ける。
- **勝利可能性**：相手のマスを通らず、今後の合法配置で獲得できるマスと自分のマスを上下左右につないで対岸まで届くこと。候補やバッグの現在の内容はリロール可能なため制限に含めない。

v0.5 の追加要件は [0.5.md](./0.5.md) に従う。

## v0.5 対戦画面

- 候補の型名は画面に表示せず、形状そのものを見せる。回転操作 `↶ Q` / `E ↷` は選択中候補のすぐ上に置く。
- ゴール棒の長さを盤面外枠の幅・高さに一致させ、上下左右の余白を揃える。左右の文字は反転させず、左右対称の縦組みで示す。
- 対戦画面の背景は手番ごとに彩度を抑えた単色。配置不可は中立色の × で示す。
- 対戦開始後は招待リンクを表示しない。遊び方は小さな `?` にし、ターン・ルーム・プレイヤー情報は補助表示に縮小する。

v0.4 の追加要件は [0.4.md](./0.4.md) に従う。

## v0.4 終盤と対戦画面

- 両者とも通常配置ができなくなったら延長配置へ移り、両者の候補を改めて3つドローする。
- 延長配置では自分のマスとの重なりを許す。相手のマスとの重なりと盤面外への配置は禁止し、少なくとも1マスは新しい空きマスに置く。延長配置でも両者とも配置不能なら引き分け。
- 対戦画面は盤面を中心とし、候補を盤面下に置く。候補の左右に `◀ A` / `D ▶`、候補の近くに `↶ Q` / `E ↷` を置く。手番は落ち着いた背景色でも示す。
- ゴール棒に輪郭を付ける。配置不可は中立色の × で示し、長い操作説明はヘルプに移す。ルーム、接続、勝敗は小さく残す。

v0.3 の追加要件は [QUADRIDGE v0.3 追加・変更内容.md](./QUADRIDGE%20v0.3%20追加・変更内容.md) に従う。

## v0.3 オンライン対戦

- ホームで表示名を入力し、ランダム対戦またはルーム対戦を選ぶ。従来のローカル2人対戦は `/local` に残す。
- 表示名は Unicode 正規化と前後の空白除去を行い、1～16文字の英数字・ひらがな・カタカナ・漢字・長音・アンダースコアを許可する。画面とサーバーの両方で検証する。表示名と内部のプレイヤー ID は別に扱う。
- ルームコードは重複しない6文字の英大文字と数字。小文字入力は大文字に直す。招待リンク `/room/ABC123` からも参加できる。対戦参加者は最大2人。
- ランダム対戦は接続中の待機者2人を自動で組み合わせる。待機を取り消した人を組み合わせない。
- WebSocket で参加、手番、配置、勝敗、切断を同期する。ゲーム状態と操作の可否はサーバーが確定し、各プレイヤーには自分の手札のみ送る。
- Cloudflare Workers、Durable Objects、静的アセット、カスタムドメイン `quadridge.reak1161.com` を公開構成とする。

基準仕様は [QUADRIDGE ゲーム設計書 v0.1.md](./QUADRIDGE%20ゲーム設計書%20v0.1.md) と [QUADRIDGE v0.2 追加・変更内容.md](./QUADRIDGE%20v0.2%20追加・変更内容.md)。

## 実装済み

- 15×15 盤面での同じ端末を使った2人対戦。蒼が先攻で上下、朱が後攻で左右を担当する。
- I/O/T/L/J/S/Z の4マスブロック。90度回転のみ、反転なし。
- プレイヤーごとに独立した7種1巡バッグと、常時3つの候補。
- 盤面内かつ空きマスなら離れた位置にも配置可能。
- 自分のマスの上下左右の辺接続による勝利判定。
- 候補選択、ゴースト表示、回転、配置、勝利経路の表示、ヘルプ。
- 3候補すべてが置けない手番の自動パス。盤面に置ける形状だけへの候補リロール。
- A / D キーで候補を選択。Q / E キーで左 / 右に回転し、候補と盤面のゴーストに向きに応じた短い演出を表示。回転角度は候補ごとに保持する。
- 画面サイズに応じた盤面・候補の縮小と、通常画面でのスクロール抑制。

## v0.1 の未決定事項に対する暫定判断

- 引き分け：v0.4 では通常配置ができなくなっても延長配置へ移る。延長配置でも両者とも置けない場合に引き分けとする。
- 先攻・担当方向：蒼が先攻・上下、朱が後攻・左右に固定。先後差の補正はしない。
- 相手の候補は手番が切り替わった時点で画面に表示する。同じ端末を交互に使用する前提。
- CPU対戦、制限時間、ランキングは対象外。オンライン対戦は v0.3 で導入し、状態共有と不正操作対策をサーバー側で行う。
- A / D キーで候補の端を越える入力は、暫定的に端で止める。設計書では未決定。
- 極端に小さいウィンドウでは読みやすさを保てない場合がある。具体的な最小画面の扱いは未決定。

## 操作と用語

- **候補**：自分の手番で選べる3つのブロック。使用した枠に新しいブロックを補充する。
- **バッグ**：各形状を1つずつ含む抽選の1巡。空になると次の7種をシャッフルする。
- **パス**：手番の候補をすべての回転・位置で試しても置けない場合、その手番を配置なしで終えること。
- **リロール**：パスしたプレイヤーの候補を、現在の盤面に置ける形状から選び直すこと。通常バッグは消費しない。置ける形状が3種類未満なら候補もその数とする。
- **延長配置**：両者とも通常配置ができなくなった後の配置。自分のマスに重ねて置けるが、少なくとも1マスは新しい空きマスに置く。
- **勝利可能性**：今後獲得できるマスを使って、自分の2つの対岸をつなげられる可能性。
- **残り距離**：判定対象の連結成分から、自分の両方の対岸までに足りないマス数の合計。
- **判定勝ち**：延長配置の終了時に、残り距離、代表経路のマス数、総占有マス数の順で優位だったプレイヤーの勝利。
- **ゴースト**：配置前に盤面へ表示される半透明の予定位置。配置できないマスにはプレイヤー色と異なる中立色の「×」を表示する。
- **接続**：自分のマスの上下左右の辺が触れていること。斜めは接続しない。
- **対岸**：蒼なら上端と下端、朱なら左端と右端。
- 候補を押すか A / D キーで選び、必要なら Q / E キーまたは左右の回転ボタンを押し、盤面の置きたいマスを押す。そのマスがブロックの左上基準位置になる。回転するのは選択中の候補だけで、候補ごとの向きは選択を外しても表示・保持する。配置後は次の手番に向けて全候補を0度へ戻す。
