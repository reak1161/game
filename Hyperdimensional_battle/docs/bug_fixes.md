# バグ修正記録

## 運用ルール

バグを修正したときは、公開パッチノートへの掲載有無にかかわらず、このファイルへ内部記録を追加する。

各記録には、可能な範囲で次の内容を含める。

- 発生日または修正日
- 症状
- 原因
- 修正内容
- 再発防止策
- 実施した検証

## 2026-10-06: 連続攻撃の演出と発動中の緑枠が一致しない

- 症状: 『電光石火』などで何回目の攻撃か分かりにくく、攻撃演出中に緑枠が次のカードへ移る。
- 原因: 緑枠が演出イベントではなく、先に計算が完了したエンジンの解決位置を参照していた。連撃の予告表示と各加点も別々で、現在の攻撃回数が表示されていなかった。
- 修正内容: 発動カードと連撃の進行を演出順で管理。着弾時に攻撃回数・加点・音を更新し、全攻撃中は発生元カードの緑枠を維持。攻撃記録のカード個体IDで、同名カードや別カードの誘発攻撃を区別。演出完了・シーク・ラウンド切替で解除。
- 再発防止策: 5回攻撃中の緑枠、次カードへの切替、別個体からの攻撃、0ダメージ、ラウンド切替、旧リプレイの回数上限を自動テスト。エンジン側でも各攻撃の発生元と属性を検証。
- 検証: 型チェック、94件の自動テスト、本番ビルド通過。ブラウザー接続が利用できず、今回の実画面確認は未実施。

## 2026-10-05: 発動しないカードで無音の間が発生

- 症状: 設置効果のみのカードなどが順番に来たとき、音も発動演出もないまま通常の発動待ち時間だけ停止する。
- 原因: 自動解決前の待ち時間が、実際の発動効果の有無を判定せず一律に設定されていた。
- 修正内容: エンジンの発動判定を共有し、発動しないステップは待ち時間0に変更。古いリプレイのイベントが増えない解決フレームも待たずに通過。保存済みのコマンドと互換性を保つため、エンジンの解決単位は維持。
- 再発防止策: 設置のみ、次のカードが対象選択を必要とする場合、エンチャントのみで発動する場合、旧リプレイの無音フレームをテスト。
- 検証: 型チェック、90件の自動テスト、本番ビルド、ブラウザーでの5ラウンド再生・画面内配置を確認。

## 2026-08-26: 追加発動・追加攻撃の演出が同時に見える

- 症状
  - 追加発動の直前に待ち時間がなく、複数回攻撃も通常のカード発動より短い間隔で表示されるため、複数の効果が同時に発生したように見えた。
- 原因
  - 自動カード解決は650ms間隔だった一方、リプレイイベント演出は追加攻撃が360ms、次の追加発動へ移る箇所が0msになる場合があった。
- 修正内容
  - 同一発動内に次の攻撃がある場合と、次のカード発動へ移る場合に、通常の自動解決と同じ650msの演出間隔を適用した。
- 再発防止策
  - 連続効果の演出間隔を自動解決間隔から共有し、個別の短い固定値を使わないようにした。
- 実施した検証
  - 型検査、エンジンテスト、Web本番ビルドを実施する。

- 再発防止策
  - 1つの説明文に複数の数値がある場合、文章上の登場順と全 `textValueBindings[].occurrence` を照合する。

  - `npm test`（72件成功）

## 2026-08-29: バトル画面右上の操作ボタンが枠からはみ出す

- 症状
  - ラウンドバフ一覧ボタンの追加後、バトル画面右上の操作ボタン列が確保済みの幅を超え、枠際ではみ出して見えた。
- 原因
  - 操作ボタンが3個から4個に増えた一方、右上領域の幅と中央表示の右余白が3個分のままだった。
- 修正内容
  - 4個のボタンと間隔を含む実幅を右上領域に確保し、枠の右端から4px内側へ配置した。中央表示の右余白も同じ幅に合わせた。
- 再発防止策
  - バトル操作アイコンを追加する際は、ボタン列の実幅と中央領域の予約幅を同時に更新する。
- 検証
  - 型検査、本番ビルド、デプロイ後の本番アセット確認を実施する。

## 2026-08-29: エンチャント効果ログが魔法効果ログと同じ色になる

- 症状
  - エンチャント由来の内側ログブロックを紫色にした結果、魔法カードの効果ログと見分けられなかった。
- 原因
  - 既存のカード種別カラーとの重複を確認せず、エンチャント色にも魔法と同系統の紫色を割り当てていた。
- 修正内容
  - エンチャント由来ログをエメラルド色へ変更し、攻撃の赤・魔法の紫・能力の青のいずれとも重ならないようにした。
- 再発防止策
  - 新しいログ種別へ色を割り当てる際は、既存の外側・内側ブロックの配色一覧と重複しないことを確認する。
- 検証
  - 型検査、本番ビルド、デプロイ後の本番CSS確認を実施する。

## 2026-08-29: カード発動音が小さい、または一部鳴らない

- 症状
  - カード発動音が全体的に小さく、初回操作直後やタブ復帰後、高速な連続発動中に一部の音が鳴っていないように聞こえることがあった。
- 原因
  - 発音ゲインが低く、AudioContextの再開完了を待たずに発音を予約していた。また、最短50msの発動間隔に対して減衰時間が220msと長く、連続音の輪郭が埋もれやすかった。
- 修正内容
  - 発音ゲインを引き上げ、AudioContextがrunning状態になったことを確認してから発音するよう変更した。キーボード操作でも音声を開始できるようにし、減衰を150msへ短縮した。設定画面に試聴ボタンも追加した。
- 再発防止策
  - 発音処理はAudioContextの状態確認と再開待機を共通で行い、最短演出間隔に対して音の長さが過度に重ならない値を維持する。
- 検証
  - 型検査、本番ビルド、設定画面の試聴操作と本番アセット確認を実施する。
