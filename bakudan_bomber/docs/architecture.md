# ばくだんぼんばー アーキテクチャ v0.2

## 配信構成

- 公開URL：`https://bakudan.reak1161.com`
- フロントエンド：Cloudflare Workers Static Assets
- API：Cloudflare Worker
- ルーム状態：Cloudflare Durable Objects（1ルームにつき1インスタンス）
- リアルタイム通信：Durable Objects WebSocket Hibernation API

## 現在の責務

Workerは静的ファイルの配信、ルーム作成、参加コードからDurable Objectへの接続を担当する。

Durable Objectは参加者、ホスト、接続状態、ルーム状態をSQLiteへ保存する。ルームコードは紛らわしい文字を除いた6文字とし、暗号学的乱数から生成する。

## セキュリティ方針

- ルームの状態変更はサーバー側で検証する。
- プレイヤーIDにはブラウザで生成したUUIDを使う。
- 名前は16文字、WebSocketメッセージは2 KiBまでに制限する。
- ゲーム実装では自分の手札だけを本人の接続へ送る。
- 山札、手番、カード効果、勝敗判定は最終的にDurable Object側を正とする。

## 段階的な移行

1. ルーム作成、参加、再接続、ホストによる開始を同期する。
2. 山札と初期手札をDurable Objectで生成する。
3. カード操作をコマンドとして受け、サーバー側で検証・解決する。
4. 接続ごとに公開可能なゲーム状態だけを投影して送信する。
5. 切断猶予とゲーム復帰を追加する。

現在は第3段階の基本カードまで実装済み。接続ごとの公開状態投影も導入し、手札内容は本人にだけ送信する。

1人テストと複数人対戦は同じゲーム処理を使用する。1人テストではDurable Object内に5人のテストプレイヤーを作り、1つのブラウザが現在の手番プレイヤーを順番に操作する。ブラウザだけで動作していた旧ローカルゲーム処理は削除済み。

山札のカード別内訳はクライアントへ送信しない。捨て札のカード種類は公開情報として送り、クライアントは初期投入枚数から自分の手札と捨て札を差し引いて「残り候補」を計算する。
