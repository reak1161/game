# 構成と実装上の判断

この文書は現行コードの構成を記録する。遊べる範囲と未確定ルールは `requirements.md`、変更履歴は `progress.md`、作業時の注意は `important_notes.md` を参照する。原典はルートのv0.1設計書と `docs/` のv0.2～v0.4差分。

## ファイル構成

- `src/special_status.ts`: 特殊牌の詳細用状態説明。手牌・河・ツモ牌・ロン対象・局イベントを参照し、得点や対局状態を変更しない。
- `tests/special_status.test.mjs`: 現在のロン対象と過去の河、運命の導きのツモ牌条件、通常／トランプの么九牌条件、神経衰弱の効果制限を確認。

- `src/draw_preview.ts`: スケスケルトンの取得予定と予約オーバーレイを生成する。山・予約・追加ツモの状態は変更しない。
- `tests/draw_preview.test.mjs`: 追加ツモ、席順変更、三人打ち、フィナーレ、予約と実ツモの牌種一致、状態非破壊を確認。実行時に共通牌変化を参照するため `.ts` 拡張子でimportし、TypeScriptのnoEmit設定で拡張子付きimportを許可する。

- `src/card_status.ts`: 能力カードの効果状態と局イベントによる説明補足。手番・対象牌による操作可否は対局側が判定する。
- `tests/card_status.test.mjs`: 発動中／使用済み、複数カードの独立状態、残数、局イベントの補足を確認。

- `src/main.ts`: 画面、対局状態、局の進行、CPUの操作、得点精算。
- `src/mahjong.ts`: 牌・カード・プレイヤーの型、牌山、和了形、役・符・点数、各種効果の計算。
- `src/style.css`: 対局画面と設定画面の表示。
- `src/yaku_catalog.ts`: 役一覧のカテゴリ、有効・無効・局イベントの対象外、設定に応じた翻数とタブの判定。得点計算には関与しない。
- `src/yaku_browser.ts`: 通常局・神経衰弱共通の役一覧。翻数タブ、全タブ検索、種類／有効状態のフィルタ、現在有効な特殊役へのショートカット。
- `src/visuals.ts`: 同梱SVGと拡張牌の共通表示、牌名の代替表示、描画差分からの演出、演出設定の保存。
- `public/assets/tiles/`: FluffyStuffのCC0牌素材とライセンス原文。出典は `docs/assets_credits.md`。
- `tests/mahjong.test.mjs`: 牌・得点・カード・イベントの回帰テスト。
- `tests/yaku_catalog.test.mjs`: ローカル役・特殊役の設定、ダブル役満OFF、槓子系役の翻数、神経衰弱・トランプマジックの対象外表示を確認。
- `tests/settings-browser.mjs`: 対局設定と主要操作をヘッドレスChromeで確認するスクリプト。
- `tests/visuals-browser.mjs`: 全37牌画像の読み込み、12拡張数牌、PC・スマートフォン表示、演出ON/OFF・設定保存・OSの動きを減らす設定を確認。画像は `artifacts/visuals/` に保存。

## 牌の描画と演出

`tileHtml` は公開特殊牌と手番外の手牌に `data-special-inspect` を付け、詳細専用のボタンを有効にする。操作対象の `data-tile` とは分離し、クリックで対局操作を行わない。通常の詳細はフォーカスでも表示する。神経衰弱の専用詳細も `specialStatus` による状態説明を使用する。

`tileFaceHtml` を手牌・河・副露・ドラ・役一覧・神経衰弱で共用する。通常牌34種と赤5牌3種は同梱SVG、10～13は数字と種類による表示。画像読み込み成功時だけ牌名の文字を視覚的に隠し、失敗時は文字を残す。操作ボタンの牌名・特殊属性のaria-labelも維持する。

`finishVisuals` は `data-visual-key` と `data-face` を前回描画と比較し、新しい牌・変わった牌・新たに表示された結果だけをWeb Animations APIで動かす。局の切り替えで履歴をリセット。ゲームの進行や乱数には関与しない。演出設定は `mahjong-motion` に保存し、保存領域が使えなくても対局は継続する。OSの動きを減らす設定を優先し、OFF時は実行中の演出も停止する。

和了結果は `ResultHand` に `Score.chosen` の採用牌をコピーして保存する。通常のロン・ツモ、複数人ロン、便乗、先を見据える、神経衰弱、フィナーレに共用し、画像表示時に得点を再計算しない。刻子牌の仮想牌と圧縮牌の2枚目は印を付ける。採用牌は得点判定の構成を表示し、固定カンは得点判定用の3枚として含まれる。実物のカン4枚は卓の公開組に残す。

`decorateResult` が通常局・神経衰弱の画像、役の変更要因、段階表示、スキップ操作を共用する。スキップ時と局変更時は `resultTimer` を解除。演出OFFまたはOSの動きを減らす設定では段階表示の待機を省略する。フィナーレは各和了の採用牌を `finaleHands` に保存し、終了画面へ渡す。

`lastDiscardId` は実際の打牌時に更新する。イレギュラー判定用の初回公開順とは別に管理し、ものひろいで拾い直した牌を再打牌した場合も直前の牌を強調する。鳴かれて河から消えた牌は強調しない。神経衰弱の盤面は裏表で同じ高さを保つ。

## 対局状態と進行

`main.ts` の `Phase` は setup、turn、claim、call、warning、finale、memory、result で画面と入力を切り替える。`startRound` が人数に応じて牌山、カード、局イベントを用意し、`drawCurrent` と `discard` が通常手番を進める。`claimMeld`、`makeKan`、`startAddedKan` は副露とカンを処理する。`botTurn` がCPUの打牌・能力使用を担当する。

ロン候補と鳴き候補は打牌後に判定する。和了点は `winScore` から `bestScore` を呼び、`settle` または `settleMultipleRon` で支払う。三人打ちの支払い、ダマスカス、トラップ、ハイリスクハイリターン、便乗などは精算側で反映する。流局時は `exhaustiveDraw` が聴牌料を扱う。

設定は開始画面の6カテゴリのポップアップから変更し、`selectedElements` とフォームを同期させる。カード・特殊牌・局イベント・特殊役・ローカル役・その他ルールの選択を開始局へ渡す。現在の対局はローカル対CPUで、ルーム対局の状態共有とホスト権限は未実装。

## 牌と和了形

`bestScore` は `fixedMeldTileIds` に含まれる虹色牌を探索インデックスから除外する。固定組の元の得点判定は維持し、残りの虹色牌のみ変化先を列挙する。全ての虹色牌が固定済みなら通常の得点結果をそのまま返す。

`scoreHand` は固定した副露・カンの各3枚のIDと牌種を採用手牌で検証し、固定組を別の手牌で置き換える候補を無効にする。`dancerRoleReachable` はテンプレートから固定カン相当の牌種を除き、残りの仮牌に固定実牌を加えて検証する。

虹色の圧縮対子は実牌IDと展開された2枚目のIDから同じ探索単位を識別し、虹色牌の候補インデックスを重複除外する。候補ごとに元の属性と保存された2枚目をコピーして共通の `changeTileKind` を適用し、保存牌種・展開牌種・赤属性を一致させる。

虹色変化の探索順序は対称性のキーごとに管理する。同じ赤／仮想属性の通常虹色牌だけを昇順制約でまとめ、和了牌・圧縮牌は独立キーを使う。異なる条件の牌間で変化先の順序を制限しない。

`fixedMeldTileIds` は副露・カンの得点判定用3枚のIDを取得し、多牌の除外候補と刻子牌の展開で共有する。`tripletVariants` は和了牌に加えて保護IDの牌を除外対象から外し、実際に採用された固定牌の特殊属性・赤ドラ・表示を維持する。

`bestScoreWithExtra` は15枚から除外する1枚を選ぶ際、`ScoreContext.kans` と `openMelds` の固定牌IDを除外対象から外す。固定組に同じ牌種の余分な牌があっても、実物の固定牌を採用結果から失わないようにする。

通常局の牌種は34種、トランプマジックでは各数牌の10～13を追加する。三人打ちの通常局は萬子2～8を牌山から除く。赤ドラ、特殊牌、公開順は `Tile` の属性で保持する。`makeWall` が人数・イベント・選択された特殊牌に合わせて牌山を作る。

`standardShapes`、`linkedShapes`、`shapeOf` と `isWinningShape` が通常形、連子形、七対子、国士無双、トランプマジックの専用形を判定する。刻子牌は `tripletVariants` で1枚を刻子に展開し、余る通常牌を除く。複数の刻子牌も同時に展開できる。`bestScore` は成立する解釈のうち最終和了点が最大のものを採用する。`scoreHand` が役、符、ドラ、カードによる翻数変更を算出する。完全な競技麻雀準拠ではなく、未対応役は `requirements.md` に記録する。

待ち牌は `waitKinds` で候補牌を加えて和了形を調べる。特殊役のON/OFFも渡し、連子形とトランプマジックの専用形は有効な役だけを待ち候補に含める。三人打ちの転調では `existingWaitKinds` が局内に現れた萬子2～8だけを待ち候補に含める。立直、フリテン、踊り子の聴牌候補もこの待ち判定を利用する。

## 対子祭りと踊り子

`dancerPatternGroups` は3種類の色移動と数字の順逆を組み合わせて最大6候補を生成する。通常は数字を10から、トランプでは14から引いて反転する。字牌は変えない。牌体系・前回と異なる牌姿・聴牌を検証し、`dancerRoleChoices` で目標役を検証して同じ役内の重複牌姿を除く。緑一色など、数字反転で条件を失う役も得点判定を通して除外する。

対子祭りは `Tile.compressedMate` に元の2枚目を保存し、手牌から1枚減らしたあと独立生成した通常牌を加える。牌山は変更しない。`compressedVariants` は圧縮牌を不可分な2枚組として展開し、14枚の通常形候補を列挙する。展開後の全体が16～28枚の異種対子なら八対子～十四対子も評価する。得点計算では圧縮された2枚目もドラ・赤ドラ・特殊効果の対象に含める。圧縮牌が変化したときは保存した2枚目も同じ牌種に変化させる。

`waitKinds` も同じ展開を使い、展開済みの牌から `compressedMate` を外して和了形を判定する。これにより待ち牌の二重展開を防ぐ。打牌時は `releaseCompressedTile` で保存した2枚目を除去し、ロン判定と河では通常の1枚として扱う暫定方式。副露候補・カン・北抜きには圧縮牌を含めない。

CPUの `botTurn` は圧縮可能な対子を繰り返し探し、追加牌ごとにツモ和了を判定する。追加牌取得後は `mayTsumo` を有効にし、最後に生成した牌IDを和了牌として扱う。圧縮済み牌は再圧縮候補から外すため、手番中の処理は有限回で終わる。

踊り子は `dancerPatterns` と `dancerRoles` に役別聴牌候補を持つ。`dancerRoleChoices` は同一役の候補を役名とともにまとめ、`dancerRoleReachable` は和了点計算で目標役が成立することを確認する。門前清自摸和も基準役に含む。配牌と自分の通常ツモ前に `danceHand` が牌種を変更する。暗槓・亜空槓があれば固定カンを残し、`dancerLooseTiles` で残りの牌だけ変化させる。固定カンが3組なら三槓子、4組なら四槓子も役別抽選へ加える。対子祭りの圧縮牌が同居するときは、圧縮牌込みの候補手牌を `dancerHandReachesRole` で評価し、目標役が成立する候補だけを採用する。圧縮牌が複数ある場合も、候補内の対子を使って圧縮位置への割り当てを最大8通り生成する。同じ牌種の対子を重複して使わないよう枚数を確認する。候補が3通り未満ならランダム配置で補う。生成済みの有限候補を重複除外して探索し、候補が見つからなければその回の変化を見送る暫定方式。

## 局イベント

フィナーレは四人打ちでは残り12牌、三人打ちでは残り9牌から公開手番に移り、全席のツモ和了を調べる。ツモ予約、立直後のツモ回数、アルティメットリーチ、カウントダウン、海底の釘も公開手番に反映する。

転調は起家（対局開始時の親）の手番開始時に確率判定し、場と牌山の数牌を1つ進める。変化後の牌種でドラ、待ち、フリテンを再判定する。トランプマジックの革命・革命返しは局のカン総数から決め、数牌ボーナス符に反映する。

神経衰弱は `memoryBoard` に裏向きの牌を置き、毎局 `openingDealerSeat` から `memorySelect`、`memoryFinishTurn`、`memoryBotTurn` で専用進行を行う。獲得した4面子と雀頭を固定して役判定し、完成時の最終和了点を3倍にする。ドラ、特殊牌配置、使用可能カードの細部は未確定であり、現在の暫定方式は `requirements.md` を参照する。

## 能力カードと特殊牌

カード使用可否は `hasCard`、使用済みは `usedCards` で扱う。CPUのロードローラー、千変万化、ランダマイザーは未圧縮の通常牌から変化対象を選ぶ。ポケットビスケットと流しマシンガンのツモ予約はプレイヤー別の `drawReservations` に保持し、`consumeDrawReservation` で消費する。借りパクとものひろいでは追加打牌と河の牌移動を状態として扱う。

ゾンビは打牌後に各ゾンビ牌が独立して増殖を抽選する。選ばれた手牌はゾンビ牌と同じ牌種のゾンビへ変化する。圧縮牌が対象なら保存された2枚目も同じ牌種へ変え、局イベントを渡して幺九牌限定の特殊効果を更新する。イレギュラーは最初に場へ4枚現れた牌種へ変化する。伝説の秘宝は役別成立条件が未確定のため、配布と得点効果は未実装。

## 検証と文書更新

ブラウザー検証は踊り子・刻子牌の併用も通常局とトランプマジック各3種の固定乱数で確認し、表示手牌の配牌時・打牌後の聴牌と開始／打牌処理時間を記録する。性能値は実行環境のサンプルとして扱い、最悪時の保証には使わない。

`npm test` と `npm run build` を基本確認に用い、対局画面の操作は必要に応じて `tests/settings-browser.mjs` で検証する。変更後は `docs/progress.md`、公開向け変更は `docs/patch_notes_public.md` もUTF-8で更新する。未確定の原典事項は `docs/important_notes.md` と `docs/requirements.md` に暫定方式として残す。
対局設定は `mahjong-setup-v1` に開始時点の値と要素選択を保存する。復元は許可された値のみを採用し、保存不可・破損データでも起動を継続する。対局の盤面や進行状態は保存対象外。演出設定の保存とは独立して初期化できる。
## 卓と説明の配置

通常対局の描画後に `arrangeTableLayout` で卓内のアリーナ・手牌・カード・副露を配置する。牌IDと打牌処理は変えず、河は6列の固定領域、相手の手牌は外周、局情報は中央へ置く。各席の副露・カンはまとめて配置し、別々の組が同じ絶対座標で重ならないようにする。

`placePopover` は説明の実寸を測り、対象の16px上へ置く。画面上端では横または下を選ぶ。特殊牌、神経衰弱の特殊牌、得点変更要因で共有する。ブラウザー標準のtitleツールチップを併用せず、牌名はaria-labelで保持する。
